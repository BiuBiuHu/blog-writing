# 文章质量：让读者愿意读，而且带走东西

## 1. 读者收益要具体

“介绍我们的迁移”是作者任务。“判断 Agent 高频发布下怎样选托管方案”是读者任务。

写清读前和读后的差别：能辨认一个误区、作出一个选择、复现一个方法，或者避免一类代价。不要把“开阔视野、引发思考”作为唯一收益。

## 2. 吸引力来自读者在乎的真实矛盾

场景里需要具体约束、代价和待解决问题；无需夸张、悬念标题或虚构情绪。技术复盘的张力往往是：原来合理的做法为何失效，什么证据促使作者改变判断。

先给读者承诺，不必隐瞒结论。读者继续读，是为了理解理由与做法。

## 3. 信息增量与作者判断

读完官方文档仍得不到的内容，是实际条件、错误假设、失败实验、决策权衡和可检验的结果。不要只把功能列表和文档翻译成长文。

每一节至少推进理解：补充事实、解释机制、检验判断、排除误用或帮助行动。重复中心句不能替代推进。

## 4. 主张要有足够完整的证据链

关键结论写出条件、行为、观测及解释；小样本不能推出长期稳定性，费用估算不能当账单，部署成功不能当业务成功。

不要用大量数字制造可信感。保留影响决策的数字，说明口径，并允许不利结果改变原先叙述。

## 5. 详略由决策价值决定

值得展开：读者容易判断错、失败代价高、难以从公开资料找到、或会改变选择的细节。

适合压缩：版本编号、重复测试清单、与主题无关的管理过程、未影响判断的时间线。审计材料留给附录或项目记录。

检查法：删除这一段，读者会更难理解或行动吗？不会，就考虑压缩或删除。必要解释不足时应展开，而不是一味追求短。

## 6. 可迁移的结论与适用边界

让读者看清实际选择所依赖的条件，必要时说明替代情形和放弃理由。案例是推理材料，不需要每次都改写成普遍定律。

教程或选型指南可以给决策顺序；实践文章也可以在真实结果或一个未解决问题处结束。不要为展示读者收益，在每篇结尾强行加一套步骤。

## 7. 从真实经历到可用的方法

个人经历应解释发生了什么、为什么改变选择、结果如何。把条件和证据写清，读者往往能自行判断是否适用；只有缺少解释会造成误用时，才补充概括，不要每节再提炼一次原则。

建议明确检查对象和行动条件。例如“评估成本”过于宽泛；“分别统计构建次数、发布次数和运行用量，再确认各自额度的时间窗口”能指导实际操作。无需为了显得具体而伪造阈值。

有多个合理方案时，给出适用条件及放弃理由；证据不足以推荐时，说明还需要测量什么。并非每篇都必须给出唯一答案。

## 8. 编辑诊断与修订优先级

诊断顺序：读者任务 → 中心判断 → 主线与证据 → 关键细节 → 句子与排版 → 搜索适配。

一个围绕高频自动发布的案例，主线可以是：工作被什么限制打断 → 原有配额如何计量 → 选择哪些交付路径 → 做了哪些取舍 → 用什么证据验收 → 读者怎样评估自己的情况。

技术细节只有在支撑上述判断时才展开。不要把一次真实事故的专属规则变成所有文章的固定要求。

| 稿件问题 | 优先修订 |
|---|---|
| 像项目结项报告，读者不知道与自己有什么关系 | 重写开头与中心问题，说明读者处境和收益 |
| 观点正确但泛泛，换一个作者也一样 | 补入实际选择、限制、失败证据和改变判断的过程 |
| 比较表很丰富，却不知道为什么选某方案 | 统一比较口径，解释哪些差异影响本次决定及代价 |
| 技术细节很多，主线不断被打断 | 保留会改变判断的细节，将其余材料压缩、链接或移至附录 |
| 故事缺少判断依据，读者难以理解为什么这么选 | 补实际条件、候选方案及证据；教程需要时再给操作方法 |
| 标题或开头承诺过大 | 收窄承诺，或补足真实证据；不用夸张措辞填空 |

这些是诊断线索，不是每篇文章必须出现的章节。先处理事实与因果错误，再补论证，随后删重复和修语言，最后检查摘要、搜索表达与站点格式。

## 9. 解释性配图与阅读体验

一幅恰当的解释图能帮助读者迅速建立心智模型，减少在段落之间反复查找和记忆的负担。把它作为编辑手段主动考虑，而不是写完之后的装饰。

- 流程及先后关系用流程图；职责边界和调用关系用架构图；数字与趋势用数据图；并列指标用表格。按要解决的理解问题选择，而不固定偏好一种形式。
- 图先突出本文要说明的差异，细枝末节留给正文。例如比较配额时区分构建、部署与运行，标明时间窗口和免费/付费边界。
- 放在读者第一次需要理解该关系的位置。图前说明看什么，图后指出它如何支持当前判断。
- 不以图片数量衡量质量。多幅重复图、装饰图和信息过密的总图可能增加负担；复杂内容需要时主动配图，简单事实不硬画。
- 文章章节和操作步骤的编号统一为阿拉伯数字，方便扫读与引用；不使用中文序号。

博客结构与流程解释图优先采用 HTML/CSS → 浏览器渲染 → PNG 截图 → 正文图片。这样可控制中文排版、间距与信息层级，读者不依赖 Mermaid 渲染器也能阅读。保留 HTML，真实检查导出结果；解释图标注为示意，不冒充现场截图。

## 10. 自然叙事与 AI 味检查

用户指出文章模板化时，优先回查动机和结构，而不是先删几个高频词。

### 开头

- 从已经发生的具体事情写起，保留作者提供的口吻与困扰。不要先用“一个此前没有那么突出的问题”“这引出了一个更普遍的问题”等通用句包装事实。
- 不强制“钩子 → 背景 → 收益承诺”。不要默认写导读、说明本文讨论什么或告诉读者读完会获得什么；只有实际有帮助时保留。
- 不通过虚构某天、时刻、场景、心理活动或对话增加现场感。真实细节不足，就朴素地写明已有事实。

### 判断过程与节奏

- 顺着改变选择的节点展开：当时遇到什么，考虑了哪条路，什么证据让这条路继续或被放弃。保留没有完美解决的部分。
- 允许篇幅不对称：重要转折多写，简单事实短写。不要把每段经历都加工成一个原则，再配同样长度的解释。
- 少用“交付资源、完整成本、资源分工”等抽象概括替代具体对象。能写构建次数、账单、接口耗时就直接写。
- 对比图和实测数据可以直接承担论证，不必在图表前后多次解释其意义；区别必要的口径说明与重复总结。
- 删除换个项目名也能通用的空段。段末不默认添加“这说明……”“核心在于……”“最值得带走的是……”；有效结论保留，但避免连续拔高。

### 结尾与事实边界

- 不默认以检查表、普遍建议或“时代变化”结束。可回到最初困扰及实际结果；仍未知的费用、性能或风险照实写明。
- 不为口语化而刻意加入俏皮话、虚假犹豫或情绪，不把严谨的不确定性全部删掉。
- 最后单读开头和各段最后一句：如果连起来像宣传提纲或一串金句，回到具体事实重写。再通读全文，确认保留的是作者的判断，不是助手在给案例配解说。
